# 精简设计与迁移安排

本文件解释 MISSION 的目标和迁移方式；状态只在 loop.md。已获用户确认并实施；最终处置与兼容边界见 [result.md](result.md)。

## 1. 目标调用方式

改造前：组织资源解析 → 部署文件读回／恢复 registry／再次解析 → 工作流入口生成组织字节 → Flow 再解析／创建回执 → TaskSpace。

目标：组织资源或部署文件在加载边界解析 → Anchor 组织模块取得任务上下文 → 通用 TaskSpace／Ctrl／Data 处理任务与结果。内部传正常对象和已有资源引用，只有真实存储／传输边界做编码。

这不是新的通用上下文协议：优先使用当前 TaskProfile、产物引用及 Anchor 组织模块，具体字段只由真实消费者决定。不得照着旧证明链设计同构的新包装。

## 2. 代码归属与公开面

| 位置 | 保留 | 删除／迁移 |
|---|---|---|
| holon `holarchy-core-contract` / `holarchy-core-logic` | 组织模型、历史查询、生效时间、对外数据兼容与输入校验 | 同一调用中 parse→normalize→canonical→digest 的重复全图校验；内部使用已解析数据的小函数，不增加证明类型 |
| Anchor `holarchy-eidolon-adapter` | 从真实资源／外部组织输入加载和校验；组织与执行配置的转换 | 内部每次投影都签发一层证明；同内容重复摘要和副本 |
| Anchor `ai-organ-logic/src/organization` | Holon 任务创建、等待、重规划、结果转换及与部署／运行的关联 | 从 flows 接回组织专用 helpers；优先整合到现有 HolonWorkflowTaskRuntime 等模块，不默认新建包 |
| flows 的 AI contract / logic / Ctrl / Data | 通用节点、任务、状态、输入产物、结果；现有通用资源装载能力 | Holon 专属 target/profile/receipt/freeze helpers 及公开导出、硬编码组织 Kind；组织回执相关依赖。不可把一般 Agent 资源冻结和加载也一并删掉 |
| Bridge | 网络输入和响应校验、草稿、连接范围、未知命令和结果关联 | 同进程内部重复 deep parse；用虚构 start/work/page/receipt 验证一个子对象 |

移动旧 helper 只是过渡，完成要检查其调用链是否真正减少；整段搬到 Anchor 继续全部包装不算达标。组织资料的完整关系检查留在写入／外部加载入口。

公开 Holon API 已随旧 Flow 包发布；不能改写旧版本。先迁移四仓当前消费者、完成隔离消费验证，再从新通用包删除组织 API。旧历史版本仍可用；不得为了旧入口让 flows 依赖 Anchor。新版本语义、导出变化与外部已知消费者清单在实施公开面变更前确定，未列全的仓外消费者风险如实记录。

## 3. 回执字段合并

采用最小迁移：保留现有消费者已使用的 `issuerReceiptId`，删除新格式中的 `issuerReceiptArtifactDigest`。该 ID 已是同一份字节的摘要，不再另算同值摘要；产物本身需要的 digest 仍使用现有 TaskArtifactRef。

- 旧记录有两个字段：读取时验证它们相等，再转换到内部单一表达；不相等视为损坏，不选择任意一份掩盖冲突。
- 新记录：按明确格式版本只写一套字段；不能向旧版 exactKeys reader 偷写不兼容对象。
- 重规划、订阅和 Inspection 继续关联原任务；原有效 ID 不因字段改名重新生成。
- 读取旧格式不触发业务操作；历史查看、迁移读取不启动任务、不写真实用户数据。
- 兼容读取保留至当前有支持义务的旧记录可正常读取；永久双写与永久双状态机不在目标形态内。

## 4. 部署资源只存一份

本次去重单位是“一个部署采用的共享资源集合”，不引入全局 CAS／新 VCS。

- 部署内复用已有文件索引／内容引用，资源实际内容保留一次。
- observation 和 Agent 清单引用部署中那份文件集合，不再各内嵌完整 files/base64。
- Agent 只保存自己的配置、消息／代码引用、确有需要的差异；不得通过引用当前工作区来省掉恢复所需输入。
- 独立导出 Agent 时按需展开为自包含包；运行期共享去重不取消独立交付能力。
- 新读取器先支持现有完整 observation / bundle 格式，再增加新格式写入；旧文件不原地删改。只在隔离复制的旧记录样本上演练转换。
- 重启后首次读取文件属于真实边界，需要完整校验；加载后内部共享对象不反复还原 registry 和重新解析。

## 5. 部署运行状态收缩

立即目标：同一不可变部署定义按其现有版本／路径身份加载后复用，不让每次状态 load/commit 重新读取全部资源和构建 registry。采用新部署时明确换对象；不新增“缓存准入证明”。

存储目标：优先一份运行状态、一个并发版本、必要业务操作记录及原子提交；不为相同状态维持两条摘要链。采用已有可用存储设施或最小原子文件写入，不为了精简建立新的持久化框架。

四仓读写者复查显示部署专属 head/tree/receipt/transaction 只有本存储及其测试消费；不同领域的 provider/session 记录链另有真实用途，未改动。

当前实现缓存不可变部署定义；新写入先同步准备状态，再原子替换 `current.json` 并同步目录，CAS 和进程锁不变。兼容读取保留旧内容校验和准备事务 roll-forward，包括首次初始化尚无 head 的窗口。新正常提交不增加旧摘要链。旧会话、订阅、终态、任务历史仍由原业务 owner 保留。具体代码与故障覆盖见 result.md / evidence.md。

## 6. 时间、版本、身份与校验的裁决

| 内容 | 最小保留位置 | 不应传播的内容 |
|---|---|---|
| 生效时间 effectiveAt | 组织历史查询；同一个历史条件可由任务上下文引用 | 每个中间包装独立保存并重新比较的完整副本 |
| 来源版本 | 组织输入选取／恢复需要的版本 | 普通函数每转一次都生成“来源证明” |
| run/node/task/command ID | 实际对象关联与幂等入口 | 为包装派生的新身份链 |
| expectedRevision | 可变数据的拥有者提交入口 | UI 投影或普通中间对象独立裁决版本 |
| 内容摘要 | 资源／产物存储和真实传输需要处 | 同字节多字段、多次计算；没有独立用途的额外语义指纹 |
| schema／格式版本 | 需要兼容读取的持久或公开协议 | 每个内部投影创建一套独立协议 |
| 校验 | 网络、磁盘、外部资源等输入边界 | 内部同一已解析对象全图重复检查 |

WeakSet 构造标记不是跨进程认证；只在仍有明确的内部误用风险且无法由已有入口保证时保留具体用途，不新增同构标记层。本 mission 不负责删除所有普通对象冻结或通用 Agent 资源检查。

## 7. 测试处置与交付

- 删除只断言旧证明名称、重复字段、已迁移导出、固定包装层数的测试；不把旧结构测试迁到新路径继续保留旧约束。
- 先辨认被这些测试覆盖的业务风险，把仍有效的坏输入、错任务、幂等、并发、旧数据、异常退出案例保留在所属包。
- 原本失败但与本次无关的基线如实记录；不能用历史绿色代替当前验收，也不扩大为另一个修复 mission。
- 选择明确包集合做一次隔离 npm pack 消费，记录实际解析位置和版本，不用邻仓 symlink 冒充跨仓交付。只复制包产物，不复制整个应用、node_modules 或运行数据。
- 最终提供逐项处置清单：原机制、删除／合并／保留结果、实际承接模块、公开面变化、兼容读取边界、验证结果。该清单是文档，不是运行期“证明框架”。
