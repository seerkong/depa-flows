# 最少机制与明确职责

本文件约束精简后的结构，不是工作清单。下面是不变量，文件是载体，代码／测试／产物是当前投影；三者不能互相替代。

## 用法与优先级

本文件管职责和复杂性；业务正确性由另一吸引子共同约束。减少代码却丢失恢复能力不合法，维持功能却换名增加证明链也不合法。实现方式可以改变，以下关系不随局部方便改变。

## 一句话关系

```text
一个业务事实 → 明确的负责模块
一个真实输入边界 → 一次必要的解析与业务检查
同一部署的共享内容 → 一份存储，其余引用
内部派生 → 普通值／已有引用，不自动产生证明
通用流程 → 任务和结果；组织模块 → 组织语义
复杂性减少 → 删除重复机制，而不是换名字包装
```

这些是评审关系，不是要在运行期新增的数据模型。

## 基本对象

| 对象 | 用途 | 不代表什么 |
|---|---|---|
| 输入边界 | HTTP、磁盘或外部资源进入当前模块 | 每一次内部函数调用 |
| 业务状态 | 任务、组织、部署运行的实际状态 | 包装层专属的第二份状态 |
| 已有引用 | 标识真实任务、资源或产物 | 由中间转换另发一层身份 |
| 共享内容 | 多 Agent 需要的同一资源集合 | 所有历史版本必须共用一份可变内容 |
| 兼容读取 | 将旧格式一次转换到正常内部表达 | 永久维护两套写入和执行协议 |

## 硬不变量

### I1 · 职责归属不随调用层数增加

✅ 组织模块理解成员、角色、生效关系；流程处理任务和结果。

❌ 流程为创建任务重新验证组织全图；Bridge 为展示组织数据复制治理模型。

### I2 · 校验跟随真实输入边界

✅ 新网络输入、磁盘读回先校验；同一已解析对象在内部传递。

❌ parse 后调用 canonical 再 normalize、再完整验证；反过来用“已经校验过”跳过另一条独立外部输入。

### I3 · 内容共享是实际共享

✅ 部署保留一份需要恢复的资源，Agent 保存自己的差异和引用。

❌ observation、每个 Agent bundle 和物理文件重复包含同一全集，只把字段改名为 reference。

### I4 · 同一事实没有平行解释

✅ 同字节摘要沿用已有引用；回执 ID 的别名在读取旧格式时转换。

❌ 为同一字节长期保留两个摘要字段，再建立一个新回执证明两者相同。

### I5 · 纯转换不自动签发证明

✅ 普通转换返回普通对象；真实副作用由执行入口返回结果和必要记录。

❌ 每次解析、投影或类型转换都创建 proof/authority/attestation、WeakSet 准入对象和独立版本链。

### I6 · 通用包不承载具体组织模型

✅ 组织任务适配使用通用 Flow／TaskSpace；组织依赖留在 Anchor 和 Holon。

❌ 为兼容旧导出让 flows 依赖 Anchor，或新增一个包装包把原耦合藏起来。

### I7 · 兼容性是有边界的读取能力

✅ 旧数据经入口适配，正常执行与新写入只有一套表达。

❌ 为“安全迁移”无限双写，或把旧包装测试全部搬过去固定第二套状态机。

## 排除集

- 新通用证明框架、专用证明 Kind、对内部值逐层签发身份和回执。
- 只移动／重命名代码却不减少重复处理或持久内容。
- 同部署同资源全集在多个 JSON/base64 容器长期重复保存。
- 用完整仓库、node_modules 或用户运行目录副本作为常规验证方式。

## 与 mission 的边界

MISSION 定义交付范围；loop 记录下一步；测试和实际产物测量这些关系。减少文件行数不能替代关系检查，测试绿色也不能为排除集开例外。
