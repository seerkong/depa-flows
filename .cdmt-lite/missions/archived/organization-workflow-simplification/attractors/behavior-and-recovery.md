# 业务语义与可恢复性

本文件约束本次精简必须持续成立的业务关系。不是实现顺序或测试清单；当前行为仍以代码、测试和实际运行观察为准。

## 用法与优先级

它与最少机制吸引子同时成立。某项重复记录确实承担业务用途时，应找出最小承载方式，而不是整体照搬旧证明链，也不是删除其业务能力。

## 一句话关系

```text
组织历史查询 → 请求的组织与生效条件
执行结果 → 原运行／节点／任务
相同执行请求 → 同一处理结果，不重复副作用
状态提交 → 当前并发版本和完整可恢复状态
旧持久输入 → 可读、可关联、不会因读取而重发
恢复所需内容 → 固定采用的输入，不依赖之后变化的源码
```

## 基本对象

| 对象 | 领域含义 |
|---|---|
| 组织历史 | 哪些成员、角色、关系在指定条件下生效 |
| 任务 | 一次明确工作及其实际生命周期 |
| 执行请求 | 可能因重试或断线重复送达的操作 |
| 运行输入 | 该次运行采用且恢复需要的内容 |
| 并发版本 | 数据拥有者判断是否允许更新的条件 |
| 历史记录 | 已发生结果及当时的关联，不是可随意重写的当前投影 |

## 硬不变量

### I1 · 历史条件具有实际含义

✅ 组织模块按 effectiveAt／必要版本返回对应组织状态，变更不会悄悄替换运行已采用的输入。

❌ 将生效时间当无用日志删掉，恢复时直接采用当前成员名单。

### I2 · 结果准确归属

✅ 保留必要 run/node/task/request 关联，错误对象不能被当前请求接受。

❌ 删除重复“身份”时一起删除跨请求串线检查，或迁移后重新生成历史任务 ID。

### I3 · 不确定不是可重复执行

✅ 同命令重复送达幂等；未知结果沿原调用查询；冲突命令明确拒绝。

❌ 断线恢复自动重新派发、通过草稿读取启动任务、为重新验收调用用户真实会话。

### I4 · 提交完整且不覆盖并发更新

✅ 失效 revision 拒绝；异常退出后恢复完整旧状态或完整新状态。

❌ 用单机或减少文件为理由删除必要锁、原子替换、持久化或尚有实际作用的事务恢复。

### I5 · 历史读取独立于新写入形式

✅ 旧任务／部署可读，新数据使用单一格式；旧副本矛盾时拒绝损坏。

❌ 只让新 fixture 通过，靠清空旧数据库完成迁移，或忽略两个旧字段不同值。

### I6 · 内容去重不改变恢复来源

✅ 多 Agent 引用部署共享的固定内容；需要独立交付时可展开。

❌ 为省存储改为读取邻仓当前源码，或者导出包缺少运行必需内容。

## 排除集

- 删除组织历史、任务幂等、终态、并发或真实边界输入检查来降低复杂性。
- 静默丢弃旧任务、会话绑定、订阅或运行结果。
- 用替身替换业务 owner／存储，或用旧版本测试证明新候选正确。
- 对真实用户数据库、运行目录或会话执行未经授权的迁移与验收。
